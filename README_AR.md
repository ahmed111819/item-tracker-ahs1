# ماسح عروض Amazon.sa

يشغّل مستودع GitHub سير عمل **Amazon.sa deal scanners** بثلاثة بوتات تعمل بالتوازي. تحفظ كل حالة منتجات في PostgreSQL على السيرفر، ويشتركون في سجل تنبيهات Telegram نفسه. السيرفر للتخزين فقط ولا يشغّل فحص Amazon.

## التشغيل

- تنبيهات الكوبون والعرض الترويجي تكون عند خصم 40% فأكثر حسب إعداد كل ماسح.
- شغّل **Amazon.sa deal scanners** من GitHub Actions مع تفعيل `continuous` ليفحص البوتات الثلاثة بالتوازي، ثم ينتظر 10 دقائق بعد اكتمالهم قبل بدء الدورة التالية.
- أوقف التكرار بإلغاء التشغيل الجاري.
- لا تشغّل نسخ Colab بالتزامن مع GitHub.

## إعداد PostgreSQL

1. اتبع `DATABASE_SETUP_AR.md` لإعداد قاعدة البيانات والمستخدم.
2. شغّل `postgres_schema.sql` مرة واحدة.
3. استورد ملفات تتبع البوتات الثلاثة وسجل التنبيهات القديم باستخدام `import_postgres.py`.
4. أضف GitHub Actions Secret باسم `DATABASE_URL` مع رابط PostgreSQL مشفر بـ TLS.
5. أبقِ `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` في GitHub Secrets.

لا يبدأ أي بوت إذا كانت حالة تتبعه أو سجل التنبيهات المشترك غير مستوردين، لتجنب تاريخ فارغ أو تنبيهات مكررة. ملف سجل التنبيهات المرفق لا يحتوي ملفات تتبع المنتجات.

## المساحة

يحفظ PostgreSQL ثلاث حالات JSON مضغوطة، صفًا ثابتًا لكل بوت (`bot1`, `bot2`, `bot3`) ويحدّث الصفوف نفسها بدل إنشاء ملفات جديدة. الحجم السابق يقارب 8.5 MB لكل حالة مضغوطة، ويجب تخصيص مساحة إضافية لـ WAL والنسخ الاحتياطية.

كل checkpoint ينقل الحالة المضغوطة بين GitHub Actions والسيرفر. التخزين يزيل الاعتماد على حصة Supabase، لكنه لا يلغي نقل البيانات.
