# item-tracker-ahs1 — ماسح عروض Amazon.sa

المستودع عام؛ لا تضع فيه رموز تيليجرام أو مفاتيح Supabase/Google أو ملفات بيانات التتبع.

## التشغيل

يشغّل سير العمل **Amazon.sa deal scanners** البوتات الثلاثة بالتوازي. لكل بوت روابطه وسجل تتبعه في Supabase، بينما تتشارك البوتات سجل تنبيهات واحدًا في Supabase يمنع إرسال التنبيه نفسه أكثر من مرة.

- يرسل الماسح تنبيهات كوبون/عرض عند خصم 40% فأكثر، وتنبيه هبوط سعر عند 80% فأكثر.
- كل بوت يستخدم عاملين للصفحات داخل كل رابط، وحد صفحات احتياطي 200 لكل رابط.
- عند تفعيل خيار continuous، يفحص كل بوت مرة، ثم ينتظر التشغيل 10 دقائق بعد انتهاء البوتات الثلاثة قبل بدء الدورة التالية.
- أوقف نسخ Colab للبوتات قبل تشغيل GitHub حتى لا تتنافس على البيانات أو ترسل تنبيهات مكررة.

## إعداد Supabase مرة واحدة

1. ادمج التغيير الذي يضيف الملف SUPABASE_SHARED_REGISTRY_SETUP.sql.
2. في Supabase افتح SQL Editor، الصق محتوى الملف وشغّل الاستعلام مرة واحدة. ينشئ دوالًا ذرية لحجز التنبيه وإنهائه، وجدولًا صغيرًا لتسجيل اكتمال نقل سجل التنبيهات.
3. في GitHub → Settings → Secrets and variables → Actions، تأكد من وجود الأسرار SUPABASE_URL وSUPABASE_SECRET_KEY، إضافةً إلى أسرار تيليجرام الحالية.
4. أبقِ GOOGLE_SERVICE_ACCOUNT_JSON وVariable باسم DRIVE_AMAZON_SA_FOLDER_ID أثناء أول تشغيل جماعي؛ تُقرأ ملفات تتبع Bot 2 وBot 3 وسجل التنبيهات القديم من Drive مرة واحدة إذا لم تكن موجودة في Supabase. بعدها يتجاوز التشغيل قراءة سجل التنبيهات من Drive. ملفات Bot 1 وملف التنبيهات نُقلت بالفعل خلال تجربة Bot 1.
5. من Actions شغّل Amazon.sa deal scanners. اترك continuous مفعّلًا للاستمرار؛ ألغِ تفعيله إذا أردت دورة واحدة فقط.

## تنبيهات

- لا تشغّل Bot 1 Supabase pilot بالتزامن مع Amazon.sa deal scanners؛ شغّل مسار البوتات الثلاثة وحده بعد تطبيق SQL.
- أي رابط لا يعرض بطاقات منتجات بعد المحاولات يظهر في الملخص كفحص غير مكتمل. حد 200 صفحة يمنع الاستمرار غير المحدود؛ إذا وصله رابط، يعرض السجل تنبيهًا بذلك.
- أوقف السلسلة من Actions عبر إلغاء التشغيل الجاري.
