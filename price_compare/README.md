# مقارنة أسعار منتج — تجربة أولية

## وضع المتصفح الجديد

التشغيل الرئيسي الآن يستخدم `browser_compare.py` وChromium عبر Playwright على Ubuntu 24.04. الوضع الافتراضي `--search-provider service`: يكتشف روابط المتاجر بالبحث العربي والإنجليزي عبر SerpApi والبحث داخل متجر Apple للمنتجات التابعة له، يستبعد روابط Google التحويلية والتواصل، ثم يفتح الروابط مباشرة في Chromium وينتظر تحميل JavaScript. يحفظ صور المصدر والمتاجر المقروءة داخل التقرير. يبقى `compare.py` مكتبة الاستخراج والمطابقة والمسار القديم.

يتطلب الوضع الافتراضي مفتاح SerpApi؛ وقد يستخدم 2 إلى 7 طلبات اكتشاف حسب الحاجة ومسار المصدر البديل طلبًا إضافيًا. الوضع الاختياري `--search-provider browser` يبحث في Google بالمتصفح مباشرة، لكنه واجه CAPTCHA فعليًا من GitHub؛ لا يتجاوز التحقق. إذا فشلت قراءة المصدر يمكن استخدام المفتاح كمسار بديل معلن في `source_method`. لا يوجد وعد بأن جميع المتاجر ستقبل عناوين GitHub السحابية. نجاح اكتشاف الرابط لا يثبت قراءة السعر أو تطابق النسخة.

للتشغيل المحلي: ثبّت المتطلبات ثم `python -m playwright install chromium`، وشغّل `python price_compare/browser_compare.py --url 'PRODUCT_LINK' --headed --output reports`. الخيار `--headed` يفتح نافذة المتصفح؛ لا يتجاوز CAPTCHA تلقائيًا.

فحص GitHub باسم `Verify live price comparison` يشترط روابط متاجر مباشرة وأسعارًا مقروءة بمتصفح، ويعرض عدد المطابقات المؤكدة مستقلًا عن أسعار تحتاج تأكيد النسخة. نجاح قراءة السعر لا يثبت تطابق النسخة.

تشغيل يدوي مستقل في مستودع البوتات الحالي. أدخل رابط صفحة المنتج، ثم يعرض التقرير اسم نطاق المتجر، سعر المنتج بالريال ورابطه، مرتبة من الأرخص. لا يحسب الشحن. لا يشغّل تيليجرام أو أي ماسح آخر.

## الإعداد في GitHub

1. ضع `compare.py` و`test_compare.py` و`requirements.txt` وهذا الملف داخل `price_compare/`.
2. ضع `price-compare.yml` داخل `.github/workflows/`.
3. أنشئ حسابًا ومفتاحًا في https://serpapi.com/ ثم احفظ المفتاح في Settings → Secrets and variables → Actions → New repository secret باسم `SERPAPI_API_KEY`. للخدمة حدود واشتراكات؛ راجع خطتك قبل التشغيل. كل تجربة تستخدم طلبي بحث، عربي وإنجليزي، وتفحص حتى عشرين رابطًا بعد حذف المكرر، بثلاثة اتصالات متزامنة كحد أقصى. مسار أمازون البديل يضيف طلبًا عند الحاجة.
4. بعد دمج الملفات إلى الفرع الافتراضي: Actions → «مقارنة أسعار منتج» → Run workflow → ألصق الرابط → Run workflow.
5. افتح Summary للنتيجة، أو نزّل artifact باسم `price-comparison` للحصول على `report.md` و`report.json` الذي يتضمن أسباب الاستبعاد. يحتفظ GitHub بالتقرير سبعة أيام. الروابط والتقرير تظهر لمن يستطيع مشاهدة تشغيل المستودع؛ استخدم رابط منتج عام خاليًا من الرموز الخاصة بحسابك.

## حدود التجربة الفعلية

آخر تحسينات القراءة: تنظيف عبارات الماركة مثل `Visit the Apple Store` وإزالة محارف العرض الخفية؛ تفضيل رابط المتجر المباشر إن أرجعته خدمة البحث مع رابط Google، وتتبع تحويلات HTTP مع فحص الوجهة؛ قبول بيانات المنتج التي تفتقد `@type` فقط مع `og:type=product` وتطابق رابط الصفحة؛ قارئ مخصص لبيانات HNAK المضمنة في الصفحة دون تنفيذ JavaScript، مع مطابقة مسار المنتج وعدم قراءة التوصيات. تُحفظ الوجهة النهائية عند فشل القراءة لتشخيص المشكلة بدل وصف كل فشل بأنه عدم تطابق.

التقرير يعرض أسعارًا تحتاج تأكيدًا في جدول منفصل إذا تطابق الاسم التجاري الكامل والماركة ولم يظهر تعارض معروف في النسخة، لكن غابت بيانات الموديل أو الحالة أو التوفر. هذه ليست نتائج مطابقة مؤكدة، ولا تُخلط معها. قد تكون بيانات المتاجر نفسها متعارضة؛ لا يستبدل القارئ الماركة المختلفة لمجرد ظهور Apple في العنوان. تحقق قارئ Apple وHNAK محليًا من صفحات فعلية لهذه البطارية بسعر 449 ريالًا لكل منهما؛ ذلك لا يثبت نجاح جميع روابط التشغيل من GitHub.

تحديث: يوجد قارئ لصفحة منتج Amazon.sa دون JSON-LD. ينظف رابط المشاركة إلى رابط ASIN، وإذا رفض أمازون القراءة المباشرة يحاول `amazon_product` عبر SerpApi بنفس المفتاح. هذا يستهلك طلبًا إضافيًا من رصيد الخدمة، وقد يتطلب دعم هذه الواجهة في الخطة. يرفض تبديل ASIN. نون لم يُدعَم بقارئ خاص بعد. نجاح استخراج الاسم لا يعني نجاح المطابقة؛ قد تبقى بيانات الباركود أو حالة العرض غير متاحة. اختبارات المسار البديل وهمية؛ لم يُتحقق من نجاحه بحساب المستخدم حتى الآن.

- تبحث باستخدام SerpApi Google Organic مع `gl=sa` و`hl=ar` ثم `hl=en` بعبارات شراء عربية وإنجليزية، مع الحفاظ على اسم المنتج ورقم الموديل كما استُخرجا. لا توجد ترجمة آلية لاسم المنتج. ثم تفتح روابط المتاجر مباشرة؛ لا تعتمد أسعار مقتطفات البحث. موقع المتجر يُعرض كنطاقه لتجنب اختراع اسم تجاري.
- تقرأ حاليًا بيانات `Product` و`Offer` من JSON-LD في HTML. ليست هناك تغطية خاصة لأمازون أو نون أو صفحات JavaScript بعد. الصفحات المحمية أو التي تفتقد هذه البيانات تفشل بوضوح. لا يوجد ادعاء بأن جميع المتاجر مدعومة.
- تقبل باركودًا عالميًا متطابقًا، أو بديلًا عنه ماركة متطابقة ورقم موديل أو MPN كاملًا وصالحًا (حروف وأرقام، خمسة رموز على الأقل) مع مواصفات نسخة متوافقة. تقرأ الألوان وعدد القطع والسعة والأبعاد والوزن والجهد والقدرة من العنوان والمواصفات. في مسار الموديل تستبعد اختلاف أو نقص المواصفات المستخرجة في أي من الطرفين. لا تعتمد تشابه الاسم. هذه قواعد محافظة لا تغطي كل أنواع المنتجات؛ عدم ظهور اختلاف في النص ليس ضمانًا لصحة بيانات المتجر. التقرير يوضح أساس المطابقة لكل نتيجة.
- تشترط سعرًا موجبًا بعملة SAR وتوفر InStock وحالة صريحة للمنتج في المتجر المرشح. لا تشترط سعر المصدر؛ إذا لم تعرف حالته تقبل فقط مرشحًا بحالة جديد صريحة، وتستبعد عناوين المصدر التي تشير إلى مستعمل أو مجدد. تستبعد الأسعار المجمعة ومجموعات المنتجات أو العروض الملتبسة. لا تحول العملات ولا تحسب كوبونات أو أسعار أعضاء أو أقساط.
- لذلك قد تعطي التجربة صفر نتائج حتى لمنتج معروف. النتيجة الصفرية ليست إثباتًا لعدم وجود أسعار أخرى. هذه نقطة بداية محافظة لاختبار الاستخراج والمطابقة على روابط حقيقية.
- لم تُختبر مقارنة حية دون مفتاح بحث ورابط منتج فعلي. الاختبارات المحلية تستخدم صفحات ثابتة وطلبات وهمية للتحقق من المطابقة ورفض النتائج المضللة.

## تشغيل محلي

```bash
python -m pip install -r price_compare/requirements.txt
export SERPAPI_API_KEY='your-key'
python price_compare/compare.py --url 'https://store.example/product'
python -m unittest discover -s price_compare -p 'test_*.py' -v
```
